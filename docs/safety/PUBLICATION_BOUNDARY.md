# 公开发布边界

本仓库的目标是公开团队有权发布的完整工程源码、接口、设计、测试和可核查证据，而不是只发布展示壳。完整开源仍必须服从安全、隐私、著作权和再分发许可。

## 必须排除或替换

- API key、密码、令牌、Cookie、私钥、无线网络与账户凭据。
- 私网地址、设备主机键、序列号、MAC、账户名、个人绝对路径和现场服务拓扑。
- 未获授权的人脸、工牌、联系方式、位置/EXIF、聊天记录和其他个人数据。
- 未公开实验原始数据、逐文档授权语料、合作方数据和禁止再分发的数据集。
- 许可证不允许再分发的模型权重、tokenizer、二进制、字体、图片或第三方源码。
- 能暴露真实设备访问方式的部署配置；公开版本只提供逻辑主机名和占位符。

真实秘密不能仅从当前文件删除：必须撤销/轮换，并扫描整个 Git 历史和 Release 制品。

## 应当公开

- 团队拥有权利的源码、固件、接口定义、配置模板和构建说明。
- 模型注册、结构、训练/转换代码、模型卡、数据来源和可公开的评估 fixture。
- 失败、拒绝、实验态和已知限制，而不是只保留成功截图。
- 脱敏后的板端回执、哈希、测试口径和复现分层。
- BOM、接线与机械信息中不泄露设备身份且经安全审查的部分。
- 获得人物/拍摄授权并清除位置元数据的比赛与项目媒体。

不能随 Git 仓库分发的大型或许可受限工件，应提供来源、固定版本、哈希、许可证和取得方式；团队有权再分发的大型视频或制品优先放在版本 Release，不把它们反复写入 Git 历史。

## 断言边界

公开文档必须区分：

- PC 编译与 actual X5 backend；
- 固定张量与真实传感器；
- shadow/assist 与动作控制；
- replay/sim-only 与真实物理运行；
- 团队真实荧光粉验证与公开电子材料/制程基准；
- 区域成绩的队伍确认与组委会正式来源。

## 发布门

正式发布前应达到：秘密扫描 0、个人/设备身份扫描 0、未知许可文件 0、媒体授权缺口 0、文档链接错误 0，并在干净 clone 中完成已声明的离线构建和测试。未通过时应保留为发布候选，不得以“先公开再清理”处理凭据或隐私。

历史兼容文件 [`docs/PUBLIC_BOUNDARY.md`](../PUBLIC_BOUNDARY.md) 仅指向本页，不再维护旧的“非核心公开”叙事。
